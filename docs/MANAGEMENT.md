# MANAGEMENT.md —— 多 Agent 协作管理手册

> 本文是 tdx-chart-3d 项目多 Agent 协作的经验沉淀（2026-11-12，管理者 ZCode + 执行者
> trae/zcode-1 + 内部子 Agent 实战总结）。新协作场景可直接套用。
> 配套文件：COORDINATION.md（任务板/所有权/留言板）、ws_protocol.md（通讯协议）、TODO.md（任务台账）。

---

## 1. 角色定义

| 角色 | 职责本质 | 本项目实例 |
|---|---|---|
| **管理者（总管）** | 唯一决策点：任务分解、所有权分配、验收、派发、事故裁决、记忆沉淀 | ZCode |
| **执行者** | 领任务 → 独立完成 → 如实上报；不做决策、不越权、不静默 | trae、zcode-1 |
| **内部子 Agent** | 管理者的手脚：并行实现具体模块，与外部执行者同等遵守文件所有权 | Agent B/C/D/E/F/G/H |

**铁律**：方向单一（管理者→执行者派发，执行者→管理者上报）；文件所有权是并发安全的唯一基石。

## 2. 管理者区块

### 2.1 开工前（准备阶段）

1. **环境核查**：工具链版本、外部服务可达性（数据湖 API 逐接口实测）、关键依赖是否存在
   （crates.io 查询），实测事实写入协议文档 §"API 实测事实"——执行者不再各自踩坑。
2. **任务台账**：从规划文档（PLAN.md）拆分任务，编号 + 验收标准 + 涉及文件 + 状态四要素齐全。
3. **协作契约先行**：接口契约（跨 crate 类型/事件签名）由管理者定义并**冻结**，
   执行者按契约并行开发；契约变更必须双方留言板确认。

### 2.2 派发循环（核心工作流）

```
分解任务 → 分配所有权（文件级隔离，禁止交叉） → 派发（WS/子Agent）
    → 执行者开工（回 chat 确认） → 定期 status 心跳
    → done 上报 → 管理者独立验收（三关复跑 + 读码抽查，不信上报自证）
    → 通过：登记 + 立即派发下一任务（队列预编排，不让执行者空转）
    → 不通过：blocked 协商 / 打回重做（3 次失败升级用户）
```

**派发任务书六要素**：目标、验收标准（可执行命令级）、文件所有权边界、必读上下文（含源码路径）、
编码规范、报告格式。并行 agent 的任务书必须包含"构建失败若指向非你所有的文件→等待重试"规则。

### 2.3 巡检循环（事件驱动 + 定时兜底）

| 触发源 | 延迟 | 动作 |
|---|---|---|
| 执行者 WS 消息（done/status/blocked） | ≤5 秒 | 哨兵日志增长 → 守望者退出 → 唤醒管理者 |
| 定时心跳 | ≤60 秒 | 强制巡检：新消息/文件活动/在线状态/服务健康 |
| 子 Agent 完成通知 | 即时 | 验收 → 派发 |
| 用户指令 | 即时 | 最高优先级 |

每轮巡检固定动作：**查新消息 → 有 done 即验收 → 按预编排队列派发 → 全员状态轮询（广播） → 重启守望者**。
无事一句话汇报，不刷屏。

### 2.4 验收纪律（真实性原则）

- **独立复跑**：执行者声称的三关（build/clippy/test）管理者必须亲自重跑；
- **读码抽查**：测试通过 ≠ 语义正确——硬约束（如时间语义/幂等键/闭合 bar）逐行核查；
- **证据留档**：验收结果写留言板，可追溯；
- **奖励诚实**：执行者报告"路径已存在未重造""我算错了已修复"这类行为要公开表扬并采信
  （真实性文化的正反馈）。

### 2.5 所有权管理

- **分配**：任务书明确"只能修改 X，禁止触碰 Y"；跨目录写文件前必须留言板声明并获对方确认。
- **转移**：任务完成后即时归还或转移给下一执行者（留言板声明），避免幽灵所有权阻塞提交。
- **紧急修复例外**：编译阻断可直接修，但必须留言板注明改动与原因。

### 2.6 事故处理（协议 §8 实战）

1. 服务中断 → **先恢复服务**（应急重启），再追责问询；
2. 问询方式：留言板正式记录 + WS 直问，给对方留"主动认领"的空间；
3. 认领后：记录整改承诺，闭环留言板；下次同类事故对照检查；
4. 实测案例：执行者 `pkill -f` 宽模式误杀生产 hub → 主动认领 + 整改（只按 PID/端口清理）
   → 管理者接受并留档，信任未受损。

### 2.7 记忆沉淀

- 一次踩坑 → 持久记忆（非显而易见的部分才写：陷阱、反直觉事实、组合经验）；
- 例：macOS PingFang.ttc 并非每机都有、epaint 对坏字体字节 panic、bevy_text 需要第二注入点。

## 3. 执行者区块

### 3.1 接入与角色

1. 连接管理者运维的服务端（**不要自建服务器**——本实战中执行者方向搞反过一次）；
2. 注册唯一名字；同名重连自动顶掉旧连接（服务端语义）；
3. **长连接**：注册后保持到会话结束，任务靠推送实时到手；短连接轮询会丢消息
   （hub v1.1 离线队列可兜底，但长连接仍是首选）。

### 3.2 任务执行循环

```
idle（无任务时上报请求派发） → 收 task → chat 确认开工
    → 关键节点 status 心跳（每文件/每 10 分钟至少一条）
    → done（改动文件清单 + 验证命令实际输出摘要）
    → idle（领下一个）
```

**blocked 语义**：契约冲突 / 编译连续失败 3 次 / 需要决策 / 配额耗尽——立即上报并挂起，
不静默、不盲试、不擅自扩大范围。

### 3.3 上报纪律

- `done` 必须附**可复核证据**：三条验收命令的实际输出摘要、改动文件清单、边界声明
  （"未触碰 X"）；
- 发现"任务本身已被别人做完"时：如实报告"路径已存在未重造"并只补增量（真实性优先于
  交付欲）；
- 过程中的失败（测试预期算错、借用错误）如实写入报告——失败记录是信任的一部分。

### 3.4 所有权纪律

- 只写自己的文件；写前看留言板有无最新转移声明；
- 他人文件的问题 → 报告，不动手；
- 任务书之外的顺手问题 → 记录上报，不扩大范围。

### 3.5 错误处理（协议 §8 矩阵摘要）

| 错误 | 处置 |
|---|---|
| 限流/超限 | 退避等待，不轰炸，通知对方预计恢复时间 |
| 服务不可用 | 退避重试 3 轮失败转 blocked |
| 配额/套餐耗尽 | 立即通知并挂起，对方暂停派发 |
| 编译失败 3 次 | blocked 附已尝试方案 |
| 测试实例清理 | **只按 PID 或端口精确清理，禁止宽模式 pkill**（本实战唯一事故即由此引发） |

## 4. 基础设施区块

| 组件 | 职责 | 运维方 |
|---|---|---|
| ws-hub（本机 WS 服务端） | 消息路由、离线队列（v1.1）、在线名单 | 管理者独占进程管理权 |
| 哨兵（probe 常驻模式） | 管理者的在线身份，接收一切上报 | 管理者 |
| 守望者（日志增长监控） | 消息即醒 + 60 秒心跳，把 WS 事件转成管理者唤醒信号 | 管理者 |
| 留言板（COORDINATION.md） | 正式记录/回退通道/所有权声明/事故档案 | 双方追加式 |
| 任务台账（TODO.md） | 任务状态唯一事实来源 | 双方各自更新自己的条目 |

**选型教训**：哨兵脚本用 **Rust**（复用项目依赖、无扫描器误报、编译期保证）优于 Python
（本实战 Python 版遭遇：安全扫描器对所有 open() 误报、脚本自身两次写坏、僵尸进程竞态）。

## 5. 实战陷阱清单（每条都真踩过）

1. **执行者自建服务器**：角色方向理解反了 → 留言板最终版角色声明 + WS 直发纠正；
2. **短连接检查模式**：注册后即退 → 长连接要求 + hub 离线队列兜底；
3. **宽模式 pkill 误杀生产进程**：测试实例清理必须按 PID/端口；
4. **同名注册竞态**：僵尸客户端与正式哨兵抢注名字 → 交接时彻底清理旧进程（kill -9 核实）；
5. **安全扫描器对 open() 一律误报**：换 Rust 实现，或字面量路径 + 非 /tmp 目录；
6. **并发配额上限**：同时派发的子 Agent 数受套餐限制 → 失败按 §8 挂起 + 队列化，槽位释放即重派；
7. **消息到达但管理者沉睡**：常驻进程不产生唤醒事件 → 守望者把"日志增长"转成"后台任务退出"；
8. **轮询空转**：执行者埋头干活时轮询无响应是正常的，done 消息不会缺席——不要因无回报而重发任务；
9. **契约冻结后再改**：并行开发中途改公共类型会打断所有下游 → 变更必须留言板确认并同步通知
   所有在途执行者。

## 6. 一页速查

**管理者每日循环**：巡检 → 验收（独立复跑）→ 派发（队列预编排）→ 记录（留言板/记忆）。
**执行者每日循环**：在线 → idle/收任务 → 干活（status 心跳）→ done（证据齐全）→ idle。
**出事时**：管理者先恢复服务再问询；执行者先 blocked 再自救；双方留言板留档。
**永不破坏**：文件所有权、真实性上报、长连接、留言板追加式记录。
